# PLISM 追加機能 PoC v0.3

作成日: 2026-10-13。既存アプリとは別のモジュール・ポートで起動する追加機能の試作です。

## 起動

Python 3.10以降、Git、JavaScript解析にはNode.jsが必要です。Pythonの外部パッケージ、npm install、外部LLMは不要です。ブラウザ用ライブラリとAcornは同梱しています。

PowerShellで:

```powershell
Set-Location C:\Users\muto1\coderabbit
python -m codegraph.poc --repo .\repos\history --base e34e61ed71f70cf30f0e43c093333e8b6c7c3bc6 --head 244203cba1bc54fa65d88803a23a2bc6c8f8ca0c --port 8766
```

http://127.0.0.1:8766/ を開きます。この環境でpythonが見つからない場合は、上のpythonを以下に置き換えます。

```powershell
& 'C:\Users\muto1\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
```

Python/JavaScript混在デモは作成済みです。別のターミナルで:

```powershell
python -m codegraph.poc --repo .\repos\poc-v03-demo --base HEAD~1 --head HEAD --port 8767
```

http://127.0.0.1:8767/ の pricing.js / pricing.py を選んでください。broken.jsは「構文エラーでも差分が読める」ことを確認する意図的な失敗例です。終了は起動ターミナルでCtrl+C。比較を変える場合は別ポートで再起動してください。サーバー開始時のGitコミットを固定して読み、作業中ファイルは対象にしません。

## 試せる内容

- 差分と全文表示。変更前・変更後の本文を別々に保持。
- 関数を選択すると使用行を一覧表示。クリックで本文の該当行へ移動し「元の差分へ戻る」で復帰。
- 全体グラフ／選択ファイルと隣接関数を切替。円の大きさは行数・異なる呼び出し元関数数・異なる呼び出し先関数数。自己呼び出しを別集計。呼び出し箇所数と関数数を分離。
- 緑は追加・変更、白い円は静的呼び出し元方向の1〜2 hopの影響候補。太線はその経路。ズーム・パン・ノード選択。
- 「複数行検索」で改行を含む文字列を入力し、選択中の版のファイル本文を完全一致検索。空白も区別。結果の行を強調。コード本文にフォーカスしたCtrl+Fからも検索欄を開けます。
- 型1構文一致、型2の限定的なローカル名変更の重複候補。新規・増加等の候補を初期表示し、既存はチェックで追加。
- 重複領域の並列表示と名前の対応、元関数の仮引数を切り出し検討の参考として表示。
- 右側に構造上の事実と作者の説明欄。作者の説明がない場合は未登録と表示。既存notes形式を `--notes PATH` で読み込み、比較版が合う情報だけ使用。
- 「解析範囲」に未対応ファイル・解析失敗・未解決呼び出しを表示。パーサーの成否と差分取得は独立。

## PoCの範囲と限界

Pythonは既存AST解析を利用。JavaScriptはAcornでトップレベルの関数宣言と変数に代入した関数を抽出し、同一ファイル内の直接呼び出しを部分的に解決します。import先・メソッド・ネスト関数・動的な再代入等を厳密には扱いません。実行時頻度や影響の完全性を保証しません。グラフは関数単位です。

円の最大尺度は変更前後で共通。最小円を確保して面積を指標に応じて増やします。関数の変更判定は本文比較で、意味の変化とは異なります。

重複は3文以上・20トークン以上の関数本体または3文の窓が対象。リテラルは保持します。型2は安全に正規化できる一部の構文だけです。群の対応は構文ハッシュ等を使うため、移動・改名・解析対象の変化で新規に見える場合があります。解析不足時は不確実として扱います。重なった候補が複数表示される場合があります。

設計意図・処理の意味の自動説明、切り出す領域の正確な入出力推定、自動リファクタリング、型3以降、Java/C++/CSS/HTML/TypeScript/JSXの構文解析は未実装。現在の説明は行数・呼び出しなどの構造情報です。

各版150解析ファイル・8MB、本文は1ファイル1MB/2万行、重複1200領域・100グループ等の上限があります。対象外や0件を「問題なし」と読み替えないでください。

既存reader/analyzer/notesを再利用します。既存アプリの起動口・画面のソースは変更していません。
