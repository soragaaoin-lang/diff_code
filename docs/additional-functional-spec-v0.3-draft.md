## 1. 目的と既存仕様との関係

外部LLM、Bitbucket、Jira、Decision連携は引き続き対象外。対象コードを実行・書き換えない。追加パーサーを導入する場合、必要なセットアップは明記し、起動時に黙ってダウンロードしない。

## 4. 共通の契約

### 4.1 比較と位置

- 比較はrepo識別子、Base/Headの解決済みコミットまたは作業ツリースナップショット、内容ハッシュで固定する。
- 使用箇所・検索結果・重複領域は必ず `side = base | head`、相対パス、ファイル内容ハッシュ、開始・終了位置を持つ。
- 表示行番号は1始まり。列の内部表現はパーサーごとに変換し、UI側はUnicode文字単位の範囲へ統一する。タブ表示幅やUTF-8のバイト位置を混同しない。
- 対応する定義が片側にない場合は「追加」「削除」と表示する。別版の行番号へ自動的に飛ばさない。

### 4.2 不完全解析

各機能の結果は `complete / partial / unsupported / failed / not_run` の状態と理由を持つ。ここで complete は宣言した解析規則・対象の処理完了であり、実行時の依存関係の完全性を意味しない。

未測定・未対応の値は null とし、0と区別する。表示上は「未解析」「対象外」「解析失敗」「解決できた範囲で0件」などを使う。未解決呼び出し件数を併記するが、ノードへの帰属が分からない未解決件数を各ノードへ無理に配分しない。

### 4.3 差分の独立性

Gitスナップショットからの本文取得・差分生成を構文解析と分離する。パーサー未導入、構文エラー、タイムアウトがあっても、取得できた本文の差分は表示する。不正なGit ref、取得権限不足、バイナリなど本文を読めない条件では、理由を示す。以前の結果を残す場合は「前回の比較」と明示する。

## 5. F01 差分を中心に読む

既存のBase/Headとhunk表示を入口として維持する。以後のジャンプ、検索、重複確認は、元の差分の選択範囲へ戻れるようにする。画面の文章説明からも同じコード表示へ移動する。

## 6. F02 使用箇所へのジャンプ

1. 差分内の関数について「使用箇所」を選ぶ。
2. Base/Head別に、呼び出し元の定義名、file:line、実際の呼び出し行を一覧表示する。複数行の呼び出しは位置範囲を保持する。
3. 選択すると、そのスナップショットの本文を開き、呼び出しの行・範囲を強調する。関数の定義先へのジャンプとは別の操作とする。
4. 「差分へ戻る」で元のファイル、side、hunk、選択範囲、スクロール位置を復元する。

履歴は現在の比較内のスタックとして保持し、連続ジャンプも戻れる。結果を解決済み／未解決候補に分ける。名前が同じだけの候補を確定した使用箇所として扱わない。定義コード120行のプレビューとは別に、対象行を取得できる本文アクセスを用意する。

## 7. F03 円の大きさの3指標切替

### 7.1 関数表示

| UI指標 | 定義 | 数え方 |
|---|---|---|
| 行数 | 選択sideの関数の宣言から末尾までの物理行数 | `end_line - start_line + 1`。範囲内の空行・コメントを含む。言語ごとの宣言範囲規則を明示 |
| 呼び出し元の数（初期値案） | この関数を呼ぶ異なる関数の数 | 解決したsource関数IDを重複排除。同一関数内の10箇所からの呼び出しも1 |
| 呼び出し先の数 | この関数が呼ぶ異なる関数の数 | 解決したtarget関数IDを重複排除。同じ関数への複数呼び出しも1 |

実行時の頻度は測定しない。右の詳細には3指標に加え、解決済み呼び出し箇所数を表示する。自己再帰は関数の広がりを表す2指標から除外し、自己呼び出しとして別表示する。モジュール直下の呼び出しやクラス生成など、関数として数えられない関係も別欄に残し、黙って落とさない。

### 7.2 ファイル表示

行数はファイル本文の物理行数とする。ネストした定義の行数を合算しない。呼び出し元・先は「異なる外部ファイルの数」に単位を切り替え、UI名も「呼び出し元ファイル数／呼び出し先ファイル数」とする。同一ファイル内の関係はこの指標から除外し、関数表示で確認する。

これはファイル内の全呼び出し元関数数とは異なる集約案であり、単位を画面上に必ず表示する。

### 7.3 描画と比較

- ノードの色は変更状態、大きさは選択した指標に専用化する。選択状態の枠線はサイズと独立させる。
- Base/Headを切替可能とし、選択sideの辺だけで計算する。削除済みBase辺をHeadの値に足さない。
- 削除・追加ノードで選択sideに値がない場合はN/A。0件の円と区別する。
- 値の増加に対して円の面積が単調に増える尺度とする。最小表示サイズと上限を設け、上限に達した場合も実数を表示する。平方根を用いた直径変換を基本案とする。
- 基準は同一比較・同一表示階層のBase/Head全対象から決める。検索や1/2 hopの切替で同じ値のサイズを変えない。指標間でサイズだけを直接比較しない。
- 指標切替で配置・選択・読了記録を維持する。変更に対応していない指標は選択不能にし、理由を示す。

## 8. F04 設計意図・説明

| 分類 | 表示内容 | 必須の根拠 |
|---|---|---|
| 作者の説明 | 明示的に提供・取得された説明の引用または要約 | 文書やコミット等の識別子、版、位置。コミット作者というだけで説明文の作者を推定しない |
| コードに基づく説明 | そのコードが行う処理について確認できること | side、ファイルハッシュ、行範囲 |
| 推測・仮説 | 設計上の狙いの可能性 | 推測であること、根拠、確認が必要な点 |

作者の理由が見つからない場合は「設計意図の説明は未登録」とする。処理内容の説明を作者の意図に格上げしない。推測欄の存在は自動推論機能の導入を意味しない。初期はローカルの明示的なメモの登録・表示を対象とし、外部LLM生成は対象外とする。

メモは適用対象の内容ハッシュと位置を持つ。変更後の同名関数に旧メモを無条件で再利用しない。本文内にコード・HTML等があってもテキストとして安全に描画する。

## 9. F05 複数行の本文検索

- コード表示内の複数行選択から「選択範囲を検索」を実行し、改行を保ったクエリを検索パネルへ渡す。複数行を貼り付けられる入力欄も用意する。
- コード表示にフォーカスがあるときのCtrl+FをPLISM検索へ割り当てる案とする。他の画面ではブラウザ標準検索を維持する。
- 初期対象は現在開いている1ファイルの選択sideの全文。行番号や装飾DOMを検索対象に混ぜない。120行プレビューに限定しない。
- 初期モードはリテラル一致。CRLF/LFを検索用に正規化し、その他の空白・インデント・大文字小文字はそのまま扱う。位置は元の本文へ戻して強調する。
- Base/Headの切替と「両方」を用意し、結果のside・行範囲を表示する。前／次で一致範囲へ移る。空クエリは検索せず、0件は選択した対象内の結果と明示する。
- 正規表現・全リポジトリ検索・空白を無視する検索は初期スコープ外。

## 10. F06 重複・類似の候補検出

### 10.1 初期の一致条件

- 型1: コメント・書式・空白の違いを除いた構文トークン列の一致。ただし文字列内部の空白など意味を持つ内容は保持する。
- 型2（限定版）: 型1に加え、構文解析で束縛先を確認できるローカル変数・仮引数の一貫した改名を許す。外部API名、属性名、演算子、リテラル値、制御構造は保持する。
- 型2は一般的な定義の全範囲をカバーするものではなく、本書で定めた限定版とUIにも明示する。意味的な同一機能を証明しない。
- 型3以降は未対応と表示する。構文解析失敗時の文字列一致を型2として代用しない。

初期対象は関数本体と同じブロック内の連続文。最小3文かつ30有意トークンを仮の閾値とし、評価用データで調整する。CSS/HTMLの単位と閾値は個別検証後に決める。機械生成物、vendor、除外ディレクトリ等は設定可能とし、除外一覧を表示する。

### 10.2 差分との関係

BaseとHeadをそれぞれ検出し、対応する領域・ペアを比較する。「新規に発生」「既存」「解消」「対応付け不明」を分ける。変更行を含むという理由だけで既存重複を新規と判定しない。ファイル移動、改名、型2の改名で対応を確定できない場合は不明のまま表示する。

ユーザー確認済みの方針として、新規を優先表示し、既存も切替表示する。各候補に一致型、正規化規則、両方のside・位置、対象言語、解析状態を表示する。「一致候補なし」は対象範囲と検出規則内の結果であり、重複がない保証ではない。

## 11. F07 関数への切り出し候補

F06の反復領域を入口に、対応するコードを並べ、共通部分と違う部分を強調する。違いが改名だけなら、改名の対応を表示し、直ちに引数追加が必要とはしない。

異なる外部値の読み取りがある場合、確認できた範囲で引数の候補を示す。結果を外へ書き戻す変数は戻り値等の検討対象として分ける。変数の束縛、制御フロー、変更可能な状態を判断できない場合は「入出力の判定未対応」とする。

return、break、continue、例外、リソース管理、非同期処理、副作用、スコープ依存などの注意を併記する。コードの自動書換え、切り出し後の同値性保証は行わない。まず関数内の反復を対象とし、クラス境界・言語をまたぐ切り出し提案は後続とする。

## 12. F08 多言語への拡張

共通データモデルを使い、言語ごとのパーサーと関係解決器を分ける。共通構文解析基盤の採用は候補であり、ライブラリ選定・検証は未実施。構文木を取得できるだけでは呼び出し先を解決できたことにならない。

| 言語 | 構文上の対象案 | 呼び出し・参照の目標 | 現状・未検証点 |
|---|---|---|---|
| Python | 関数・クラス・連続文 | 既存ASTを基礎に拡張 | 既存call解析あり。新規機能と重複検出は未実装 |
| Java | メソッド・クラス・連続文 | 解決できるメソッド呼び出し | 未実装。型・オーバーロード・継承等を検証するまで○としない |
| JavaScript | 関数・メソッド・連続文 | 解決できる呼び出し | 未実装。動的プロパティ・クロージャ等を限定する |
| C++ | 関数・メソッド・連続文 | 解決できる呼び出し | 未実装。マクロ、テンプレート、ビルド設定、関数ポインタ等を限定する |
| CSS | ルール・宣言群 | カスタムプロパティ等の参照 | 未実装。カスケードを含む実効的な解決とは区別する |
| HTML | 要素・DOM断片 | 明示的な読み込み・参照 | 未実装。動的DOMや実行時の関係は対象外 |

CSS/HTMLの参照数は関数数と同じ指標名にしない。関数指標はN/Aとし、将来の参照指標は別の意味・単位として提示する。複数言語が混在する場合、言語別に適用機能・対象外・失敗数を表示する。

## 13. 条件別の機能表

| 条件 | diff / 本文検索 | 使用箇所・サイズ指標 | 重複・切り出し | 説明 |
|---|---|---|---|---|
| 本文取得・対応言語の解析が成功 | 利用可 | 解決範囲で利用可 | 対応した検出型のみ | 現版に適用できるものを表示 |
| 一部の呼び出しが未解決 | 利用可 | 既知の値と未解決を区別 | 構文情報の取得状況による | 未解決を断定で埋めない |
| パーサー未導入・言語未対応 | 本文取得可能なら利用可 | N/A。本文行数は利用可 | 未対応 | 適用版が確認できるメモのみ |
| 構文エラー・解析失敗 | 本文取得可能なら利用可 | 部分結果の対象を明示 | 成功範囲のみ、または失敗 | 旧説明を現版として表示しない |

## 14. 版が変わったときの通知

再解析時に比較対象の内容が変わった場合、「比較内容が更新されました」と旧・新の比較識別情報を表示する。旧スナップショットのジャンプ履歴・検索結果・重複結果・確認済み記録を新しい位置へ黙って流用しない。旧記録は削除せず参照可能にする案とする。

説明は一致する内容ハッシュなら適用可能とし、不一致なら「旧版の説明・再確認が必要」と表示する。パーサーや検出規則の版だけが変わった場合も再計算の対象を示す。Git refの表示名変更のみで内容が同一なら、内容変更通知は出さない。

## 15. 実装順序案

1. PythonとJavaScriptを初期対象に、side付き本文アクセスと差分の独立性を整える。JavaScriptのパーサー・束縛解析・解決できる呼び出しの範囲を選定し、能力表を先に用意する。
2. 使用箇所ジャンプ・戻り、本文の複数行検索を実装する。
3. 円の3指標と右側の実数、集計範囲を実装する。
4. 説明の出典分類と版変更時の失効表示を実装する。
5. PythonとJavaScriptの型1・限定型2検出、新規／既存比較を実装する。束縛を解決できないJavaScriptの領域は型2対象外と明示する。
6. 重複を入口とする切り出し候補表示を追加する。
7. 両言語の受入後、Java・C++・CSS・HTMLの対応順序を別途決め、能力表・言語別の受入試験を更新する。

各段階で利用可能な機能だけを公開し、未実装項目を対応済みとして表示しない。初期対象をPythonだけで完了扱いにせず、JavaScriptについても機能別の対応範囲と試験結果を揃える。historyに加え、JavaScriptの正常・未解決・構文エラーを含む評価用fixtureを用意する。

## 16. 受入試験案

| ID | 対象 | 合格条件 |
|---|---|---|
| A01 | diff独立性 | 構文エラー・パーサー未導入でも取得できた差分と本文を読める |
| A02 | ジャンプ | 複数使用箇所から指定sideの呼び出し行へ移動し、元の差分範囲へ戻れる |
| A03 | ジャンプ版 | 削除ノードのBase行をHeadへ誤って適用しない |
| A04 | 呼び出し数 | 1関数から10箇所のcallは呼び出し元数1・箇所数10。別の関数から1箇所加えると元数2になる |
| A05 | 指標のside | Baseの削除辺がHeadの値に入らない。自己再帰、モジュール直下のcallは別表示 |
| A06 | 指標の単位 | ファイル内callを外部ファイル数に加えず、行数にネスト定義の二重計上がない |
| A07 | 指標の画面 | 0とN/Aを区別し、切替で選択・配置を維持。検索後も同じ値のサイズが変わらない |
| A08 | 検索 | 改行を含むクエリがCRLF/LFの本文で見つかり、元の行・文字範囲を強調する |
| A09 | 検索範囲 | 120行以降の一致も見つかる。行番号表示・HTML装飾文字列を検索しない |
| A10 | 説明 | 作者の説明とコード説明と推測が区別され、未登録を推測で埋めない |
