# 使用検討・方式検討

## 参照と採用する体験

CodeRabbitはAIレビューに加え、変更の文脈を理解するChange Stack等の機能を説明している。
今回の参照は「変更概要→詳細→根拠→確認」という流れである。
公式情報は2026-10-10に確認: [概要](https://docs.coderabbit.ai/)、[PRレビュー](https://docs.coderabbit.ai/guides/code-review-overview)。
元画像のCodegraphはUI方向性の参考。画像の点／線すべての内部仕様を確認したわけではないため、内部実装を推測して複製しない。

## 使用場面

| 場面 | 入力 | 確認したいこと |
|---|---|---|
| 自分のAI生成コードをcommit前に確認 | HEAD→WORKTREE | 変更の位置、caller、ルールに該当する注意点 |
| 他人のブランチをレビュー | main→feature | ブランチ全体で変わった定義、読み順 |
| 過去変更を理解 | SHA-A→SHA-B | 当時のコードと削除前の呼び出し根拠 |
| ノイズを評価 | 同じ比較・depth 1/2 | 確認対象が増える理由と経路 |

`base→head`の直接比較を採用する。PRのmerge-base比較が必要なら利用者がmerge-baseのSHAをbaseに指定する。
チェック済みは「利用者が確認した」というメモ。レビュー承認やマージ許可とは独立した情報。

## 構成比較

| 選択 | メリット | 負担／制限 | 判定 |
|---|---|---|---|
| 標準HTTP＋静的JS | 追加Python依存なし、配布が小さい | API検証などを自前で持つ | 今回採用 |
| FastAPI | 型付きAPI、拡張しやすい | 依存管理と配布手順が増える | 多利用者／API拡張時に再検討 |
| Cytoscape.js | グラフ操作・描画・レイアウトが揃う | 大規模グラフの性能調整が必要 | 同梱版を継続 |
| D3／独自Canvas | 描画を細かく制御できる | 選択・探索・グラフ操作の実装が増える | 今回見送り |
| AST＋Git＋ルール | 再現可能、根拠を提示、ローカル動作 | 動的dispatchや意味的バグを推論しない | 今回採用 |
| ローカルLLM | コードを外部送信せず説明可能 | モデル導入・ハードウェア・精度評価が必要 | 要件確定後 |
| 外部LLM | 高度な意味理解候補 | コード送信、費用、認証、品質管理 | 現スコープ対象外 |

## 優先順位

1. 誤った依存関係を根拠付きに見せない。未解決は未解決のまま表示。
2. 変更の概要・位置・call経路から実コードへ遷移できる。
3. 確認状況とレポートで人間の作業を支援。
4. その基盤を使ったAIレビューは別の品質評価対象として追加。

## 運用と保存

解析結果はプロセスのメモリに保持する。コードや確認状況を第三者に送らない。
確認記録は同じブラウザのlocalStorage、レポートは利用者のダウンロード先に保存。
localStorageが禁止されている環境では、確認状態を現在のページのメモリで保持し、保存不可と表示する。
作業ツリーの内容が変わればスナップショットIDが変わり、以前の確認済みを自動的に適用しない。
depthだけを切り替えたときは同じスナップショットを使い、確認記録は維持する。
