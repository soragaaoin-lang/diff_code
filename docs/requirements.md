# 要件定義書 — PLISM Change Review v1

作成日: 2026-10-10 / 版: 1.0 / 状態: 実装・受入試験対象の初版

## 1. 目的

AIが生成した変更を人間が読む際に、差分を読む前に「どこが変わったか」「どの呼び出し元を確認すべきか」を把握できるようにする。
製品の参照候補はCodeRabbit。元画像で示されたCodegraphを核に、変更を確認するローカル作業画面を作る。
今回の利用者はplismの開発者／レビュー担当者。リポジトリをローカルに持ち、比較するGit refを指定できる人を想定する。

## 2. スコープと前提

前回の明示要求（Python、ローカル、外部LLM・Bitbucket・Jira・Decision連携なし）を継承する。
「rabbitcode」がCodeRabbitを指すか、AIによるレビュー指摘までを要求するかは確認中。
今回の共通基盤では、変更概要、Codegraph、差分、読む順番、静的チェック、確認記録、レポートを実装する。
静的チェックはルールベースの確認候補であり、LLMによる意味理解レビューを実装したものとして扱わない。
正式なAIレビューはモデル、実行環境、コード送信範囲、コスト、レビュー品質の合意を経て別途追加する。

## 3. 利用フロー

1. ローカルGitリポジトリとBase / Headを指定して起動。
2. 全体グラフと変更ファイル・変更定義数で今回の規模を掴む。
3. 変更ノードを選び、Base / Headコードと差分を確認。
4. 影響候補を選び、変更ノードへ至るcall経路と呼び出し行を確認。
5. 静的チェックで示された注意点を確認し、読む対象を確認済みにする。
6. 確認状況を含むMarkdownレポートをローカルにダウンロード。

## 4. 機能要件と受入条件

| ID | 要件 | 受入条件 |
|---|---|---|
| R01 | Git比較 | WORKTREEとコミット比較を区別し、コミット指定時に作業ツリーを混ぜない |
| R02 | AST定義／call抽出 | 関数・async関数・クラス・モジュールをノード化し、解決したcallにfile/lineを付ける |
| R03 | 変更判定 | 追加・削除・変更を定義に対応付け、ファイル名に空白・日本語があっても対応する |
| R04 | 影響候補 | caller方向へ1/2 hopを探索し、候補ごとに変更までの証拠経路を持つ |
| R05 | 全体グラフ | 通常は暗色、変更は緑、影響候補／経路は白、Base由来は破線 |
| R06 | ノード詳細 | file/line、callers/callees、Base/Headコード、差分hunkを確認できる |
| R07 | 操作 | 検索、ズーム、パン、全体表示、depth切替、再解析が使える |
| R08 | レビュー導線 | 変更→1 hop→2 hopの順に読む一覧と、変更ファイル差分を表示 |
| R09 | 静的チェック | 変更に関連するsignature変更、可変デフォルト引数、bare except、eval/execを根拠行付きで表示 |
| R10 | 確認記録 | 読む対象を確認済みにでき、同一スナップショットの再読込で復元される |
| R11 | レポート | 比較情報、変更、影響根拠、チェック、確認状況をMarkdownに出力 |
| R12 | 不完全解析の明示 | 構文エラーや未解決callを隠さず、他のファイルは表示する |

## 5. 非機能要件

- N01: Python 3.10+、Git、ブラウザで動作。Python追加依存は不要。
- N02: 127.0.0.1のみで待ち受け、実行時の外部通信なし。対象コードを実行・変更しない。
- N03: エラー時に既存画面を保ち、理由を表示。状態の保存不可でも解析画面は使える。
- N04: リポジトリ文字列はHTMLとして実行せずテキスト表示する。
- N05: 数百ノード程度をPoC対象とする。大規模リポジトリの性能SLAは別途測定する。
- N06: 既存ファイルを確認して変更し、更新前コピーを保存する。sources/は参照専用。

## 6. 検証と未確定事項

自動テストは要件IDと対応付ける。ブラウザで操作を確認し、結果はtest-report.mdに残す。
実際のplismのパス、過去変更の代表ケース、利用者による理解時間の比較は未確定。
理解時間の短縮は未実証。評価案は、同じ難易度の変更を用意し「変更関数・直接caller・2 hop経路」を答えるまでの時間と正答率を従来diffと比較する。
目安は各手法3ケース以上・4人程度。最初の実験で中央値と誤答を記録し、数値目標を決める。

## 7. 将来フェーズ

AIレビュー（説明・バグ候補・修正案）、import／データ依存、型推論、他言語、PR連携、Decision連携、大規模解析を順に検討する。
各フェーズで入力、期待出力、品質評価、運用条件を合意してから実装する。
